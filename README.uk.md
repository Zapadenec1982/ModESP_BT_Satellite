# modesp-bt-satellite

[English](README.md) · **Українська**

Прошивка для оригінального ESP32, яка приймає звук з телефона по Bluetooth і віддає його
**хосту** — іншому мікроконтролеру: звук по I2S, усе інше по UART. Лише звук і його керування:
розширювач портів, що віддавав хосту вільні GPIO, вилучено 24.10.2026.

Що таке хост, на вимоги не впливає, тож цей проект цього не знає і знати не мусить. На тому
кінці дроту — друга, незалежна реалізація того самого протоколу.

## Що вміє

- **A2DP sink** із SBC, AAC, aptX і aptX HD, а з підтягнутим декодером — і LHDC V5 (див.
  [Збірка](#збірка)). 44,1 і 48 кГц, а для LHDC V5 і 96 кГц, якщо хост сказав, що прийме. LDAC
  немає навмисно: єдиний доступний декодер не має ліцензії.
- **AVRCP controller**: назва, виконавець, альбом, позиція, стан відтворення, абсолютна
  гучність, транспортні команди та обкладинка альбому як мініатюра JPEG.
- **Вихід I2S**: слоти 16 або 32 біти, формат Philips, без MCLK. Тактує пристрій, а з протоколу
  1.9 лінк може тактувати хост, і тоді пристрій веде лише дані.
- **Лінк керування**: UART 460800 8N1, кадри COBS із CRC-16. Хост дізнається формат потоку до
  першого семпла. Налаштування Bluetooth, підтвердження спарювання і список спарених телефонів
  показує й міняє хост.
Без Wi-Fi, мережі, екрана, файлів, OTA і GPIO для хоста.

## Залізо

ESP32-WROOM-32 на платі DevKitC. Не S3, C3 чи C6: Bluetooth Classic є лише в оригінального ESP32,
а без нього немає A2DP. WROOM, а не WROVER, бо на WROVER GPIO16 і 17 зайняті під PSRAM.

| Сигнал | GPIO |
|---|---|
| I2S BCLK | 13 |
| I2S WS, DOUT | 26, 27 |
| UART TX до хоста, RX від нього | 17, 16 |

WS і DOUT лежать поруч у лівому ряду гребінки, BCLK — на 13, біля GND. На 25, поруч із WS, він
наводив на WS хибні фронти (перенесено 04.10.2026). Пара UART лежить разом у правому ряду; 17 і 16
— ще й IOMUX-піни UART2, тож 460800 бод не йдуть через матрицю GPIO.

Та сама прошивка має другу конфігурацію — для **голого модуля**: лінк переїжджає на UART0, TX 1 і
RX 3, саме ту пару, яку слухає ROM-завантажувач, тож хост і прошиває пристрій, і говорить з ним по
одних двох дротах (EN та IO0 теж веде хост). Консоль там вимкнена. Це вибір у Kconfig
(`SAT_LINK_PORT`), який робить збірка з `sdkconfig.bare`; див. [`docs/DEVICE_SPEC.md`](docs/DEVICE_SPEC.md),
«Голий модуль».

Процесор працює на 240 МГц: на 160 декодер aptX не встигав.

## Збірка

ESP-IDF прибитий у [`idf.pin`](idf.pin) (v5.5.5). Стоковий Bluedroid у режимі A2DP sink уміє лише
SBC, тому стек патчиться: `tools/setup.*` копіює `components/bt` зі збереженого IDF, накладає
`patches/` і копіює зверху `bt_overlay/`. Спільний IDF на диску лише читається. Подробиці — у
[`docs/BASE.md`](docs/BASE.md).

Windows, PowerShell:

```powershell
. C:\Espressif\tools\Microsoft.v5.5.5.PowerShell_profile.ps1
$env:IDF_COMPONENT_CACHE_PATH = "D:\P4_DSP\.idf_cache"
.\tools\setup.ps1
idf.py set-target esp32
idf.py build
idf.py -p COM13 flash monitor
```

Linux:

```bash
. ~/.espressif/tools/activate_idf_v5.5.5.sh   # або $IDF_PATH/export.sh
tools/setup.sh
idf.py set-target esp32
idf.py build
```

`components/bt` генерується і в git не потрапляє; `tools/setup.sh --clean` (`-Clean` на Windows)
будує його наново. Прошивка й логи на стенді — **COM13**. COM12 — це хост, а не ця плата.

LHDC V5 потребує декодера, якого в цьому репозиторії немає; чому — у [`lhdc.pin`](lhdc.pin).
`tools/setup.sh --with-lhdc` (`-WithLhdc` на Windows) підтягує його на прибитому коміті в
`components/lhdcv5_decoder`, теж поза git, а вмикає накладка `sdkconfig.lhdc` нижче. Без накладки
декодер не збирається; з накладкою, але без декодера, збірка зупиняється і каже чому.

Інші збірки — це накладки, кожна — файл `sdkconfig.*`, який називають у командному рядку:

| Накладка | Що збирає |
|---|---|
| `sdkconfig.bare` | голий модуль: лінк на UART0 (GPIO1/3), консоль вимкнена |
| `sdkconfig.linkonly` | лише лінк: HELLO, PING/PONG, LOG |
| `sdkconfig.loopback` | повну прошивку з UART, замкнутим сам на себе всередині чипа |
| `sdkconfig.clockprobe` | вимірює такт I2S на самій платі й пише його в лог |
| `sdkconfig.lhdc` | LHDC V5 з декодером від `--with-lhdc`; поєднується з будь-якою з накладок вище |

```bash
idf.py -B build_bare -D SDKCONFIG=build_bare/sdkconfig -D SDKCONFIG_DEFAULTS="sdkconfig.defaults;sdkconfig.bare" build
```

## Тести

```bash
CC=gcc PYTHON=python3 tools/run_host_tests.sh      # Windows: .\tools\run_host_tests.ps1
```

Набори збираються звичайним компілятором і плати не потребують: кадр, CRC і розкладка кожного
повідомлення з еталонними векторами від хоста, правила перереєстрації кінцевих точок і
налаштувань Bluetooth, а також прогони справжнього коду стека, лінка, обкладинок, аудіо й LHDC на
заглушках. Частині з них потрібен `components/bt`, тож спершу `tools/setup.*`; прогону LHDC ще й
`--with-lhdc`, без нього він пропускається. Пройдений прогін — це ще не результат на телефоні чи
стенді.

`.github/workflows/build.yml` на кожен push робить setup, збірку і хост-тести в офіційному
контейнері `espressif/idf:v5.5.5`, раз як є і раз з LHDC V5.

## Структура

```
components/satlink/        протокол: COBS, CRC-16, кадри, усі повідомлення. Без IDF, тестується на хості
components/lhdcv5_decoder/ декодер LHDC V5: підтягує setup --with-lhdc, у git не потрапляє
main/link.c                транспорт UART, черги відправлення й політика відкидання
main/bt_av.c               A2DP sink, AVRCP controller, спарювання й налаштування, що бачить хост
main/audio_out.c           вихід I2S, кільце PCM, підстроювання такту
main/board.h               усі номери пінів проекту, і більше ніде
bt_overlay/                цілком наші файли стека: каркас кодеків, декодери
patches/                   дельта стека Bluetooth, один diff на одну логічну зміну
tests/host/, tools/        хост-тести і скрипти, що їх запускають; скрипти setup
```
